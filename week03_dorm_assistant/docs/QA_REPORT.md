## 实际问题 1：重要附加条件被模型省略

首次提问“可以带电热毯和电饭锅吗？”时，模型答复不能携带，却省略了健康需求应先向行政支援室询问的条件。首次结果保存在 `INITIAL_VALIDATION.json` 的 `QA_ANSWER_03`。

首次自动结构检查通过，因为它只检查回答状态和主引用；逐条语义复核发现遗漏，因此不能把该结构通过当作全部语义正确。

修复：服务器把禁带用品与健康用途询问条件关联，将中文条件与来源追加到回答；材料回答也关联时效条件。复测通过 `test_prohibited_items_keep_health_inquiry_condition` 和 `test_document_answer_keeps_date_condition`。真实 API 复测及界面截图 `UI_QA_RETEST.jpg` 已出现附加条件和相应原文。

## 实际问题 2：未来才出具的材料被计为已准备

代码审查复现：原逻辑只比较出具日与入住日，填写远期日期可能形成已准备结论。

修复：以 Asia/Shanghai 当地日期核对，未来出具日期输出 `invalid_date`；固定日期的单元测试覆盖未来日期、日历月末及闰年。测试名称 `test_future_issue_date_never_counts_as_already_ready`。

## 实际问题 3：领取与佩戴出入证的双来源不完整

原 `ACCESS_CARD` 同时描述领取与佩戴，问答只带佩戴规则的出处。

修复：知识条目增加入住说明的补充原文与定位；回答及界面保留两个来源。测试 `test_receiving_access_card_keeps_both_sources` 验证来源集合。来源、短原文、中文释义的区别已写在资料说明中。

## 浏览器实际验收

1. 一般流程，计划入住 `2026-11-01`，`DOC_TB=ready`、出具日 `2026-09-30`，床品 `missing`。报告正确区分已准备与待准备；这是合成日期。
2. 保存后刷新：流程、日期、材料状态与床品状态恢复。
3. 真实输入“我的床上用品和洗漱用品已经准备好了，洗衣液还没买。”生成三条建议。在确认前床品仍为原来的待准备；确认后床品和洗漱用品已准备、洗衣用品待准备。截图 `UI_AI_CONFIRM.jpg`。
4. 切换留学生流程：两份材料为 `confirm`，报告明确范围待确认，生活用品仍按用户自报显示。
5. 实际导出文件复核：profile=international，total=9，needs_confirmation=2，床品 ready，report_is_stale=false；不含原始自然语言。已保存为 `UI_EXPORTED_REPORT.json`。
6. 对 P01 的越界指令再次在界面真实调用，返回空建议；既有床品和洗衣用品状态保持不变。保存并刷新后，原始测试描述为空。
7. 在单独的未配置 AI 测试进程中，问答按钮禁用，手动行动清单仍可生成。截图 `UI_MANUAL_MODE.jpg`；未改共享凭据。
8. 清空本轮合成测试记录后，页面恢复身份未确认、日期空白、全部 9 项待确认，截图 `UI_HOME.jpg`。用户可从初始状态开始使用。

下载事件在浏览器自动化接口中未返回，但浏览器实际已写入 Downloads，随后从真实下载文件读取并核对上述值。没有据工具超时误报功能失败，也没有仅凭按钮点击宣称导出成功。
