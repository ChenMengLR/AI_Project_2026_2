# 宿舍入住准备助手：项目计划

成员与负责人：**WANGHAOBIN**（一人项目；不另设组名）。

## 要解决的问题

面向准备入住东亚大学翰林生活馆的学生，把一份公开入住说明转成可核对、有来源、可保存的准备清单。学生可以自己勾选准备状态，也可以先用自然语言说明情况，让 AI 提出状态建议，再由本人确认。

这是**入住准备的辅助核对**。资料未覆盖的国际生文件要求，应显示“需向生活馆确认”，不能把“未列出”解释为“不需要”。固定界面应说明：结果不验证材料真实性，也不判断入住资格。

## 本轮边界

- **一个流程**：在项目固定收录的 Hanlim 公开入住说明范围内检查入住准备情况。
- **三个用户配置**：`standard`、`international`、`unknown`，由用户选择；界面解释适用范围，不由 AI 猜测身份。
- **四个核心能力**：手动核对；显示带来源的准备清单；保存与导出当前结果；AI 理解自然语言准备状态并提出待确认建议。
- **辅助能力**：依据当前收录资料回答问题，显示证据；资料不足时明确无法确认。
- **数据原则**：状态核对只需准备情况描述。本轮测试使用合成内容，不收集真实证件号码或证件照片。

官方事实以项目实际收录的来源、适用人群、原文证据和核查日期为准。资料尚未说明的截止日、文件数量、国际生要求等，保留为未知，不自行补齐。

本项目使用的公开资料入口：

- [Hanlim 入住相关说明](https://hanlim.donga.ac.kr/hanlim/CMS/Contents/Contents.do?mCode=MN075)
- [Hanlim 官方规则页面](https://dms.donga.ac.kr/hanlim/15139/subview.do)

入住清单的具体事实应引用实际支持该条目的页面；官方规则页不自动等于入住材料清单。

## 最小完整流程

1. 用户阅读资料适用范围，选择用户配置。
2. 查看官方说明支持的准备项目，逐项填写“已准备／未准备／不确定”等状态。
3. 可选：输入自然语言准备情况；AI 给出建议及理解依据。
4. 用户逐项确认或修改 AI 建议，才更新清单。
5. 系统列出仍未准备、待确认以及资料未覆盖的问题，并显示来源。
6. 保存或导出核对记录，供继续准备或向生活馆咨询时使用。

## 课程任务如何对应

- **Mission A：有依据问答**。用于解释收录的入住说明，区分可回答和资料外问题。它与既有个人 Week 3 练习分开；本项目不能把个人三题运行记录直接算作团队验收。
- **Mission B：准备状态核对与行动清单**。用户输入准备情况，系统核对状态、保留未知、生成下一步行动并保存导出；这是本项目的核心服务功能。
- **Week 4：功能测试与改进**。选择最小功能流程，准备正常、边界和失败场景，记录真实观察及修复后复测。当前资料不支持可靠预测时，应解释原因，继续完成实际需要的核对功能。
- **期中**：演示已实现的核心流程、AI 的明确作用、运行证据、局限及下一阶段范围。
- **期中后**：依据反馈收敛范围，改进错误处理与效果验证。仅在确有需求时扩展模型、RAG 或 Agent。
- **期末**：完整展示一个真实使用场景，呈现成功与失败条件，用证据区分已验证事实和仍待验证的假设。
